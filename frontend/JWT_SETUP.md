# JWT Authentication Setup Guide

This guide explains how JWT authentication has been integrated with better-auth and your Spring Boot backend.

## Overview

JWT tokens are now automatically generated by better-auth and included in all API requests to your Spring Boot backend. The backend validates these tokens and enforces role-based access control.

## Configuration

### 1. Environment Variables

Add the following environment variables to your `.env.local` file (or `.env`):

```env
# Better Auth Configuration
BETTER_AUTH_SECRET=your-secret-key-change-this-in-production-min-32-characters
AUTH_SECRET=your-secret-key-change-this-in-production-min-32-characters

# JWT Secret (MUST match Spring Boot backend)
JWT_SECRET=your-jwt-secret-key-min-256-bits-for-security

# Better Auth URL (optional, defaults to http://localhost:3000)
NEXT_PUBLIC_BETTER_AUTH_URL=http://localhost:3000

# Backend API URL (optional, defaults to http://localhost:8080)
NEXT_PUBLIC_API_URL=http://localhost:8080
```

**IMPORTANT**: 
- The `JWT_SECRET` must match the `JWT_SECRET` configured in your Spring Boot backend (`backend/demo/src/main/resources/application.properties`)
- Use a strong, random secret (at least 32 characters for BETTER_AUTH_SECRET, 32+ bytes for JWT_SECRET)
- Never commit secrets to version control

### 2. Generate Secure Secrets

You can generate secure secrets using:

```bash
# For BETTER_AUTH_SECRET (32+ characters)
openssl rand -base64 32

# For JWT_SECRET (32+ bytes, 256+ bits)
openssl rand -base64 32
```

## How It Works

### 1. Better-Auth JWT Plugin

The JWT plugin has been added to your better-auth configuration (`frontend/src/lib/auth.ts`):

```typescript
plugins: [
  nextCookies(),
  jwt({
    secret: process.env.JWT_SECRET,
    expiresIn: 60 * 60 * 24, // 24 hours
  }),
]
```

### 2. Client-Side Token Access

The auth client (`frontend/src/lib/auth-client.ts`) includes the `jwtClient` plugin:

```typescript
export const authClient = createAuthClient({
  plugins: [jwtClient()],
});
```

This allows you to get JWT tokens using:
```typescript
const token = await authClient.token();
```

### 3. Automatic Token Injection

Two utilities have been created to automatically add JWT tokens to API requests:

#### Option A: Axios Client (`api-client.ts`)
```typescript
import apiClient from "@/lib/api-client";

// Automatically includes JWT token in Authorization header
const response = await apiClient.get("/api/business/getPendingBusiness");
```

#### Option B: Fetch Wrapper (`api-fetch.ts`)
```typescript
import { apiGet, apiPost, apiPut, apiDelete } from "@/lib/api-fetch";

// Automatically includes JWT token
const data = await apiGet("/api/business/allBusinesses");
const result = await apiPost("/api/business/addBusiness", formData);
```

## Usage Examples

### Using Axios Client

```typescript
import apiClient from "@/lib/api-client";

// GET request
const response = await apiClient.get("/api/business/getPendingBusiness");
const businesses = response.data;

// POST request
const response = await apiClient.post("/api/business/addBusiness", formData);

// PUT request
const response = await apiClient.put(`/api/business/${id}/approve`);

// DELETE request
const response = await apiClient.delete(`/api/business/${id}`);
```

### Using Fetch Wrappers

```typescript
import { apiGet, apiPost, apiPut, apiDelete } from "@/lib/api-fetch";

// GET request
const businesses = await apiGet<Business[]>("/api/business/allBusinesses");

// POST request with FormData
const result = await apiPost("/api/business/addBusiness", formData);

// POST request with JSON
const result = await apiPost("/api/users/create", { name: "John", email: "john@example.com" });

// PUT request
const result = await apiPut(`/api/business/${id}/approve`, {});

// DELETE request
await apiDelete(`/api/business/${id}`);
```

### Manual Token Access

If you need to access the token directly:

```typescript
import { authClient } from "@/lib/auth-client";

const token = await authClient.token();
console.log("JWT Token:", token);
```

## Token Expiration

- JWT tokens expire after 24 hours (configurable in `auth.ts`)
- When a token expires, the backend will return a 401 Unauthorized response
- The client should handle 401 errors and redirect to login or refresh the session

## Troubleshooting

### Token Not Being Sent

1. Ensure `authClient` is properly initialized with `jwtClient()` plugin
2. Check that the user is logged in (session exists)
3. Verify environment variables are set correctly

### 401 Unauthorized Errors

1. Check that `JWT_SECRET` matches between frontend and backend
2. Verify token hasn't expired
3. Ensure user has a valid session in better-auth

### CORS Issues

1. Verify backend CORS configuration allows your frontend origin
2. Check that credentials are being sent (handled automatically by the API utilities)

## Security Notes

- JWT tokens are stored securely by better-auth (not in localStorage)
- Tokens are automatically included in requests but never exposed in client-side code
- Always use HTTPS in production
- Rotate secrets regularly
- Never log or expose JWT tokens in client-side code
